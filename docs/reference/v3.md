# v3 preview API reference

Use the [v3 guide](../guides/v3-preview.md) for setup and complete workflows. `client.secrets`, `client.numbers`, and `client.campaigns` are the same resource instances as `client.v3.secrets`, `client.v3.numbers`, and `client.v3.campaigns`. `client.v3` is additive; `client.agents`, `client.telephony`, `client.phoneNumbers`, and `client.agentManagement` retain their v2 meanings.

## Calling conventions

Every REST method has `(request, options?)` and returns `HttpResponsePromise<T>`. Awaiting it returns the parsed `T`; `.withRawResponse()` returns `{data: T, rawResponse}`. Only `list` allows an omitted request. All requests accept optional `appid`, defaulting to `client.appId`; an explicit value selects another project for which you must have authorization. Empty path identifiers fail locally and path components are encoded.

Body and query fields use their wire names, such as `agent_name`, `started_after`, and `sip_trunk`. Path/header fields use `id`, `agentSessionId`, `ifMatch`, `ifNoneMatch`, and `idempotencyKey`. Method tables below omit the common optional `appid` and second `options` argument. Types prefixed `V3.` are exported through `import type { V3 } from 'agora-agents'`; their full schemas are in [types.ts](../../src/v3/types.ts).

| Request option | Type | Behavior |
|---|---|---|
| `timeoutInSeconds` | `number` | Overrides client timeout; v3 fallback is 60 seconds |
| `maxRetries` | `number` | GET retry count; writes always use zero retries |
| `abortSignal` | `AbortSignal` | Cancels the request |
| `authorization` | `string` | Overrides the complete Authorization header; must use `agora token=...` |
| `headers` | Header-name map | Additional per-call headers; values may be strings, header suppliers, null, or undefined |
| `queryParams` | `Record<string, unknown>` | Additional/overriding query parameters |

Header suppliers follow the existing `BaseRequestOptions` contract. Authentication comes from the same client settings as v2; Basic credentials and internal gateway/region headers are rejected. PATCH sends `Content-Type: application/json`.

## Agents: five operations

Agent IDs identify stored configurations, not running v2 agents. `AgentCreateRequest` requires `agent_name`; optional body fields are `instructions`, `messages`, `greeting`, `variables`, `pipeline`, and `filler_words`. `AgentPatchRequest` permits partial updates and explicit nulls.

| Method and request | HTTP path relative to project | Parsed return |
|---|---|---|
| `agents.create(request: V3.AgentCreateRequest)` | POST `/agents` | `V3.AgentResponse` |
| `agents.list(request?: ResourceListOptions)` | GET `/agents` | `V3.AgentListResponse` |
| `agents.get({id: string})` | GET `/agents/{id}` | `V3.AgentResponse` |
| `agents.update(request: {id: string; ifMatch: string} & V3.AgentPatchRequest)` | PATCH `/agents/{id}` | `V3.AgentResponse` |
| `agents.delete({id: string})` | DELETE `/agents/{id}` | `V3.AgentDeleteResponse` |

`update` requires the current ETag as `ifMatch`. Delete has no conditional header parameter in this contract. Create has no idempotency-key parameter; a name is not an upsert key. Responses use `agent_id`.

## Secrets: eight operations

Values are write-only. Set names and key names contain 1–64 letters, digits, underscores, or hyphens. Create/replace need at least one key; deleting the last key from a set is rejected by the backend—delete the set instead.

| Method and request | HTTP path relative to project | Parsed return |
|---|---|---|
| `secrets.create({name: string, secrets: Record<string,string>})` | POST `/secrets` | `V3.SecretSet` |
| `secrets.list(request?: ResourceListOptions)` | GET `/secrets` | `V3.SecretList` |
| `secrets.get({name: string})` | GET `/secrets/{name}` | `V3.SecretSet` |
| `secrets.update({name: string, secrets: Record<string,string \| null>, ifMatch?: string \| null})` | PATCH `/secrets/{name}` | `V3.SecretSet` |
| `secrets.replace({name: string, secrets: Record<string,string>, ifMatch: string})` | PUT `/secrets/{name}` | `V3.SecretSet` |
| `secrets.delete({name: string, ifMatch: string})` | DELETE `/secrets/{name}` | `V3.SecretDeleted` |
| `secrets.setKey({name: string, key: string, value: string, ifMatch?: string \| null, ifNoneMatch?: '*' \| null})` | PUT `/secrets/{name}/keys/{key}` | `V3.SecretKey` |
| `secrets.deleteKey({name: string, key: string, ifMatch?: string \| null})` | DELETE `/secrets/{name}/keys/{key}` | `V3.SecretDeleted` |

In `update`, a string adds/rotates a key and null removes it. `replace` removes omitted keys. Replace/delete require a **set ETag**; optional `setKey`/`deleteKey` `ifMatch` uses a **key ETag**. `setKey` with `ifNoneMatch: '*'` creates only; supply that or `ifMatch` according to your intent. `setKey` returns `{key}`, never the value.

Secret and number creation do not support idempotency keys. An explicit obsolete `idempotencyKey` argument or header fails locally; writes are never automatically retried.

## Numbers: five operations

`V3.NumberCreate` requires `number` and `sip_trunk: {hostname: string, ...}`. Optional fields include `description` and `inbound`. SIP options include `port`, `transport: 'udp'|'tcp'|'tls'`, and optional `auth: {username,password}`. Each app/project registers its own numbers.

| Method and request | HTTP path relative to project | Parsed return |
|---|---|---|
| `numbers.create(request: V3.NumberCreate)` | POST `/numbers` | `V3.NumberResponse` |
| `numbers.list(request?: ResourceListOptions)` | GET `/numbers` | `V3.NumberListResponse` |
| `numbers.get({id: string})` | GET `/numbers/{id}` | `V3.NumberResponse` |
| `numbers.update(request: {id: string; ifMatch: string} & V3.NumberPatch)` | PATCH `/numbers/{id}` | `V3.NumberResponse` |
| `numbers.delete({id: string})` | DELETE `/numbers/{id}` | `V3.NumberDeleteResponse` |

Updates require `ifMatch`; delete does not. Responses use `number_id`. `inbound.agent` holds the stored agent ID; null unassigns it. `inbound.call_policy` supports `max_call_duration_seconds` and `max_silence_duration_ms`. Staging rejects deferred `end_call`, `transfer`, `allowed_ips`, and secret-reference SIP passwords.

## Sessions: five operations

| Method and request | HTTP path relative to project | Parsed return |
|---|---|---|
| `sessions.start(request: V3.SessionStartRequest)` | POST `/sessions` | `V3.SessionStartResponse` |
| `sessions.startEphemeral(request: V3.EphemeralSessionStartRequest)` | POST `/sessions/ephemeral` | `V3.SessionStartResponse` |
| `sessions.stop({agentSessionId: string})` | POST `/sessions/{id}/stop`, no body | `Record<string, never>` |
| `sessions.list(request?: SessionListOptions)` | GET `/sessions` | `V3.SessionList` |
| `sessions.get({agentSessionId: string})` | GET `/sessions/{agent_session_id}` | `V3.SessionResponse` |

Responses use `agent_session_id`. Start returns `{agent_session_id, status, create_ts}` with status `STARTING` or `RUNNING`. The SDK also normalizes rollout responses containing `created_at` and lowercase statuses; raw HTTP status and headers remain available. Retrieve statuses are uppercase: `IDLE`, `STARTING`, `RUNNING`, `STOPPING`, `STOPPED`, `FAILED`. Analysis may be absent, skipped, or contain a result. Session update and conversation actions are not implemented by this backend.

`start` requires `agent_id` and `transport`; `startEphemeral` substitutes a full inline `agent` without its stored name. Both accept `values`, `labels`, `lifecycle`, `data_policy`, and optional `idempotencyKey` (header). `client_reference` is unsupported. RTC transport includes `channel`, `uid`, exactly one non-wildcard `subscribe_uids` entry of the same numeric/string type (agent UID `0` auto-selects), optional `token`, `encryption`, and `audio_scenario`. Low-level telephony transport uses a registered number UUID in `from` and an E.164 `to`. See the [generated session types](../../src/v3/session-schema.ts) for complete fields and enums.

Lifecycle fields use milliseconds: `idle_timeout_ms` (0–3,600,000), `max_duration_ms` (1,000–3,600,000), and `graceful_stop`. The AgentKit convenience options use seconds for `idleTimeout` and `maxDuration`. Retention `none` disables extraction. Stop sends no body and returns `{}`; 404 and 409 propagate. A start idempotency key is retained for 24 hours: retry an unknown outcome with the same key/body, but use a new key for a new session. A keyed AgentSession handle cannot restart after its first successful start.

Neither session list nor retrieve exposes the stored agent ID. Names are not unique, so `saved.listSessions()` is unavailable; project-wide listing works.

## Campaigns: eight operations

Use `client.campaigns` (also `client.v3.campaigns`). Types are generated from the engineering schema; no local campaign scheduler or retry algorithm is implemented.

| Method and request | HTTP path relative to project | Parsed return |
|---|---|---|
| `campaigns.create(request: V3.CampaignCreate & {idempotencyKey?: string})` | POST `/campaigns` | `V3.CampaignResponse` |
| `campaigns.list({status?, limit?, cursor?, order?}?)` | GET `/campaigns` | `V3.CampaignListResponse` |
| `campaigns.get({id: string})` | GET `/campaigns/{id}` | `V3.CampaignResponse` |
| `campaigns.update(request: V3.CampaignPatch & {id: string; ifMatch: string})` | PATCH `/campaigns/{id}` | `V3.CampaignResponse` |
| `campaigns.delete({id: string})` | DELETE `/campaigns/{id}` | `V3.CampaignDeleteResponse` |
| `campaigns.pause({id: string, idempotencyKey?: string})` | POST `/campaigns/{id}:pause` | `V3.CampaignResponse` |
| `campaigns.resume({id: string, idempotencyKey?: string})` | POST `/campaigns/{id}:resume` | `V3.CampaignResponse` |
| `campaigns.cancel({id: string, idempotencyKey?: string})` | POST `/campaigns/{id}:cancel` | `V3.CampaignResponse` |

Create and actions support 24-hour idempotency keys; action bodies are empty. PATCH requires an ETag: pacing fields merge while other supplied fields replace their prior values. Creation supports up to 5,000 inline contacts. A telephony source is a registered number UUID, not its E.164 string. Contact time zones override the schedule time zone for local calling windows. Backend retry behavior for schema fields `max_attempts` and `backoff` remains unconfirmed; their presence in types is not a promise of execution. Separate contacts and events resources are not exposed.

`campaigns.listAll(request?, options?)` yields `V3.CampaignResponse` items with the same cursor protections as other resources. Campaign list limit is 1–200, default 50; order is `create_ts.asc` or `create_ts.desc`, and `status` filters campaigns.

## Pagination

`ResourceListOptions` and `SessionListOptions` below are documentation shorthand for the inline method parameter types, not separately exported aliases:

| Option | Agents, secrets, numbers | Sessions |
|---|---|---|
| `limit?: number` | Agents/secrets: 1–200; numbers: 1–100 on staging; default 50 | At least 1; default 20; no maximum declared in the snapshot |
| `cursor?: string \| null` | Opaque continuation cursor | Same |
| `order?: 'create_ts.asc' \| 'create_ts.desc'` | Supported | Not supported |
| `channel?: string \| null` | Not supported | Channel filter |
| `status?: string` | Not supported | Comma-separated statuses; default `RUNNING` |
| `started_after?: number \| null` | Not supported | Start timestamp lower bound (Unix seconds) |
| `started_before?: number \| null` | Not supported | Start timestamp upper bound (Unix seconds) |

Each list returns `{data:{count,list}, has_more, next_cursor}`. Every resource additionally offers `listAll(request?, options?)`, an `AsyncGenerator` of items. Item types are `V3.AgentListItem`, `V3.SecretSet`, `V3.NumberResponse`, and `V3.SessionSummary`, respectively. `listAll` throws if the server advertises more pages without a usable new cursor. These iterator helpers do not add REST operations.

```ts
// Standalone reference example: supply an already configured client.
import type { AgoraClient } from 'agora-agents';

async function readStoppedSessions(api: AgoraClient): Promise<void> {
  for await (const item of api.v3.sessions.listAll({ status: 'STOPPED', limit: 100 })) {
    const detail = await api.v3.sessions.get({ agentSessionId: item.agent_session_id });
    console.log(detail.agent_session_id, detail.analysis?.result);
  }
}
```

## Responses, errors, and retries

`await method(...).withRawResponse()` exposes ETag, `Agora-Request-Id`, Location, and other response headers through `rawResponse.headers.get(...)`. Preserve ETag strings exactly, including quotes. The `data` field is the same parsed body returned by a normal await.

`V3Error` exposes `statusCode`, `body: unknown`, `rawResponse`, and `requestId: string | null`; backend error bodies typically contain `detail` and `reason`. Transport failures may have a synthetic status/body rather than the backend error shape. Do not assume every thrown error is `V3Error`: input checks and AgentKit mapping also throw locally.

`PreconditionFailedError` extends `V3Error` for HTTP 412. `await error.latest()` returns `unknown`, since it can load any resource, and never retries the write. It preserves per-call request options while stripping conditional/idempotency write headers; secret-key conflicts reload the parent set. For a typed read use the appropriate `get` method.

GET retries inherit `maxRetries` (default 2). All writes use zero automatic retries regardless of that option. AgentKit number assignment makes one explicit fresh GET/PATCH retry after a 412; agent redeploy does not. Preview transport logging is disabled to avoid emitting tokens and write-only credentials.

## AgentKit surface

| Signature | Result / behavior |
|---|---|
| `agent.withVariable(name: string, definition: VariableDefinition)` | New Agent; local validation, no request |
| `secretRef(set: string, key: string): SecretRef` | Validated branded string, no request |
| `agent.save(options?: {name?: string; agentId?: string}): Promise<SavedAgent>` | POST without ID; GET+conditional PATCH with ID |
| `saved.createSession(options: SessionOptions): AgentSession` | Idle session; start/stop/get-info via stored identity |
| `saved.update(config: Agent, options?: {name?: string}): Promise<SavedAgent>` | Save revised configuration to this ID; same client required; preserves name by default |
| `SavedAgent.get(client: AgoraClient, agentId: string): Promise<SavedAgent>` | GET stored agent |
| `saved.listNumbers(): Promise<V3.NumberResponse[]>` | Scan all project number pages at limit 100; filter `inbound.agent === saved.id`; no per-number GETs |
| `saved.delete(): Promise<void>` | Delete stored config |
| `saved.assignNumber(number: string \| V3.NumberResponse, options?: {maxCallDurationSeconds?: number; maxSilenceDurationMs?: number}): Promise<V3.NumberResponse>` | Resolve number, GET ETag, PATCH inbound assignment |
| `saved.unassignNumber(number: string \| V3.NumberResponse): Promise<V3.NumberResponse>` | Same flow with `inbound.agent: null` |

`SavedAgent` exposes readonly `id`, `name`, `etag`, and `raw`; `raw` is the **agents resource**, so `saved.raw.update(...)` is available. A handle is a snapshot; GET a new one after another process changes it. `save` defaults the name to `agent-${Date.now()}` even for an update, so pass `name` when updating through that option, or use `saved.update(config)` to preserve the handle’s name. It has no `idempotencyKey`, strict-mode opt-out, or per-call transport-options parameter; use the low-level methods when you need those transport controls.

AgentKit errors exported by the package are `UnsupportedFieldError` (`fields: string[]`), `SecretRefNotSupportedError`, and `NumberNotFoundError`, alongside the v3 transport errors above. Invalid secret components or variable definitions also throw locally. See the [guide’s mapping and replacement limits](../guides/v3-preview.md#mapping-supported-by-deployment) before migrating a builder.

`DeployOptions` aliases `SaveOptions`; `Agent.deploy()` delegates to `Agent.save()`, and `DeployedAgent` is the same class as `SavedAgent`. These compatibility names remain available. `SaveOptions` has optional `name` and `agentId`; prefer `saved.update(config)` when updating an existing handle.
